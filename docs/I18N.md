# Interface languages

The site is English by default and ships a Russian translation. English is the project
language: documentation, comments, identifiers, API and MCP messages, and the default UI.

## Stack

- `@nuxtjs/i18n` (vue-i18n) with `strategy: 'no_prefix'` — URLs do not change with the
  language (`/weapons`, not `/ru/weapons`).
- Locales: `en` (`en-US`) and `ru` (`ru-RU`), declared in `nuxt.config.ts`.
- Catalogs are lazy JSON files in `i18n/locales/en.json` and `i18n/locales/ru.json`
  (`langDir: 'locales'`, the module's `restructureDir` is `i18n`).
- `app/app.vue` calls `useHead(useLocaleHead())` so `<html lang>` follows the locale and SSR
  renders the right language.
- `app/plugins/i18n-locale.ts` persists the explicit choice in the `dossier_lang` cookie
  (one year, `SameSite=Lax`) and applies it before rendering, so SSR and hydration agree.
  Browser auto-detection is disabled deliberately (`detectBrowserLanguage: false`): the site
  is behind a session, and guessing from `Accept-Language` would flip the language for the
  same user across devices.
- `app/components/LocaleSwitcher.vue` is the switcher in the header (and on the sign-in
  page).

## What is translated

Interface chrome: navigation, page headings, table headers, empty states, hints, buttons,
form labels, modal titles, toasts, aria labels, error messages and freshness badges.

## What is not translated

Game data stays exactly as it comes from the sources and seeds:

- item names, skins, artifact names (`АК-12`, `Нервяк`, `Обрез Chiappa Triple`);
- stat labels and category names imported from the legacy dossier/EXBO (`Пулестойкость`,
  `Автоматы`, `комбинированная`);
- ranks and qualities stored in the database (`Отмычка`, `Редкий 141%`);
- user-authored content: build titles, notes, recommendations, earnings text.

This boundary is deliberate: translating stored data would invent values and break the
`name_norm` matching used by writes, prices and MCP.

## Key layout

| Namespace | Used by |
|---|---|
| `common.*` | shared buttons, yes/no, dry-run strings, toasts, the section stub |
| `nav.*` | header navigation and page titles |
| `auth.*` | sign-in page |
| `ranks.*` | `RankBadge`, rank filter options |
| `errors.*` | API error codes mapped by `useApiError` |
| `sources.*` | source ids and statuses in settings |
| `overview.*`, `table.*`, `filters.*` | overview page and shared tables |
| `weapons.*`, `armor.*`, `containers.*`, `artifacts.*`, `items.*` | section pages and item cards |
| `builds.*`, `recommendations.*`, `earnings.*`, `notes.*`, `settings.*` | section pages |
| `events.*` | event log, rollback dialog |
| `forms.*` | edit modals (gear, character, build, content block, container fill) |
| `freshness.*` | freshness badge |

Both catalogs must have exactly the same keys and the same `{param}` placeholders. That is
enforced by `tests/unit/i18n-catalogs.test.ts`.

## Adding a string

1. Add the key to `i18n/locales/en.json` with English text.
2. Add the same key to `i18n/locales/ru.json` with the Russian translation and identical
   placeholders.
3. Use it in the component through `const { t } = useI18n()` and `t('namespace.key')`.
4. Run `npx vitest run tests/unit/i18n-catalogs.test.ts`.

Rules:

- No concatenated sentences: use placeholders (`{count}`, `{date}`), not `t('a') + value`.
- Do not put game data into catalogs.
- Keep keys semantic (`items.deleteConfirm`), not textual (`items.deleteItemQuestion`).

## Adding a language

1. Add the locale to the `locales` array in `nuxt.config.ts` with a `file` in
   `i18n/locales/`.
2. Copy `en.json` to the new file and translate every value, keeping keys and placeholders.
3. Add the code to `SUPPORTED_LOCALES` in `app/plugins/i18n-locale.ts`.
4. Extend `intlLocale` in `app/composables/useFormat.ts` if the language needs a specific
   Intl locale, and check the money suffixes in `packages/shared/src/format.ts`.
5. Add the language to the parity test base keys if it becomes required, and add the entry
   to `LocaleSwitcher.vue` (the label uses the language's own name).
6. Run `npm run check` and `npm run e2e`.

## Server and MCP messages

API and MCP messages are English (`server/utils/errors.ts`, `server/utils/auth.ts`,
`packages/core/src/services/writes.ts`, `packages/mcp/src/registry.ts`). The error
envelope and codes are unchanged.

The web UI localizes known codes with `app/composables/useApiError.ts`:

```ts
const { message } = useApiError();
message(code, serverMessage); // known code → t(`errors.${code}`), else serverMessage, else errors.generic
```

`useWrite`, the sign-in page and the settings sync toast use it, so a Russian UI shows
Russian errors while the API stays English. Suggestion lists (`details.suggestions`) are
item names and stay as sent.

`diff.human` is English because it is produced by the service layer; the UI shows it as-is
in toasts and modal alerts.

## Formatting

`packages/shared/src/format.ts` accepts an optional locale:

- `num`, `g1`, `g2` — separators and decimal comma for `ru`;
- `fmtMoney`, `compactNum` — `K`/`M` for English, `тыс.`/`млн` for Russian.

`app/composables/useFormat.ts` binds them to the active locale and also formats dates and
ages. Never format dates with `toLocaleString()` without a fixed locale: SSR and the client
must produce the same string, otherwise hydration mismatches.

## Tests

- `tests/unit/i18n-catalogs.test.ts` — key and placeholder parity.
- `tests/unit/use-api-error.test.ts` — error-code mapping and fallbacks.
- `tests/unit/shared.test.ts` — locale-aware number formatting.
- `tests/e2e/i18n.spec.ts` — switching to Russian, a translated heading, persistence after
  reload, switching back to English.

E2E assertions use the default English interface; the Russian run is isolated in
`i18n.spec.ts`.
